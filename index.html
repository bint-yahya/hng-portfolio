01 · WCAG 2.1 AA + DESIGN SYSTEM

Colour System & Accessibility

All colours below have been verified to meet WCAG 2.1 AA contrast requirements. The accent #D4884A is the WCAG-safe version of the original copper — it passes 4.5:1 on dark backgrounds for normal text. Violet #A78BFA passes similarly on dark. Every text/background pairing must be checked before shipping.

⚠ CRITICAL WCAG REQUIREMENTS — APPLY SITE-WIDE

  • Normal text (under 18px / 14px bold): minimum contrast ratio 4.5:1
  • Large text (18px+ regular or 14px+ bold): minimum contrast ratio 3:1
  • UI components and focus indicators: minimum 3:1
  • Muted text #9A9AAC on #09090E achieves ~5.2:1 — acceptable. Never go darker/lower than this for body-size text.
  • Card borders: use solid #2A2A38 in dark mode, #D0CAC0 in light. This fixes the "cards disappearing into background" bug — never use a bare rgba() border that can fail at low screen calibrations.
  • All interactive elements must have a visible focus ring: outline: 2px solid #D4884A; outline-offset: 3px — never remove focus outlines.
  • Font size minimum for body text: 16px (1rem). Labels/tags minimum 12px.
  • Line height minimum 1.6 for body text. Letter-spacing for mono labels: 0.06em minimum.
  • All images must have meaningful alt text. Decorative images: alt="".
  • Respect prefers-reduced-motion — wrap all Framer Motion animations and disable/reduce if true.
  • The dark/light mode toggle must have an accessible label: aria-label="Switch to light mode" / "Switch to dark mode".
  • Body font: Inter 16px exclusively for body text. Playfair Display is for headings/display only.
  • Minimum interactive touch target: 44×44px on all buttons and links.

CSS IMPLEMENTATION

  • Define all tokens as CSS custom properties on :root (dark mode defaults). When <html data-theme="light">, override the tokens — every component automatically respects both modes with no conditional logic.
  • Card borders: border: 1px solid var(--border) where --border is #2A2A38 dark / #D0CAC0 light. Always a solid colour, never a bare rgba().
  • Body font: Inter 16px, line-height 1.7. Headings: Playfair Display. Labels/tags: Space Grotesk. Load all three from Google Fonts.
  • Minimum interactive touch target: min-height: 44px; min-width: 44px on all buttons and links.

TYPOGRAPHY STACK

  • Display/Headings: Playfair Display — Google Fonts. Use for h1–h3, pull quotes, and hero tagline. Weight 700 for hero, 600 for sub-headings.
  • Body: Inter — all paragraph text, descriptions, UI labels. Weight 400 regular, 500 medium. Minimum 16px for body copy.
  • Mono/Labels: Space Grotesk — eyebrow labels, tags, nav links, category chips, all-caps headings. Letter-spacing 0.08–0.15em depending on size.

TYPE SCALE

  • h1 — 3.2rem / Playfair Display 700
  • h2 — 2.2rem / Playfair Display 600
  • h3 — 1.5rem / Playfair Display 600
  • h4 — 1rem / Playfair Display 600
  • body — 1rem (16px) / Inter 400, line-height 1.7
  • label — 0.75rem / Space Grotesk 500, uppercase, tracked
  • tag — 0.7rem / Space Grotesk 500

BACKGROUND TEXTURE

Apply a subtle SVG grain noise texture as a pseudo-element overlay across the entire body. Opacity 0.025–0.035. This removes the flat digital feel and adds tactility. Use: background-image: url("data:image/svg+xml,...noise-filter...") or a repeating PNG grain tile at low opacity.

02 · LIGHT / DARK MODE

Theme Toggle Implementation

Dark is the default. The toggle sits in the navigation bar — to the right of nav links on desktop, and inside the hamburger overlay at the top on mobile.

TOGGLE COMPONENT SPEC

  • Visual: a small pill toggle — moon icon (🌙) for dark, sun icon (☀️) for light. 44px minimum touch target. Icon changes on switch.
  • Accessible: role="switch", aria-checked="true/false", aria-label="Switch to light mode" (updates dynamically).
  • On click: toggle data-theme attribute on <html> between "dark" and "light". Store preference in localStorage key "theme". On page load, read localStorage first, then check prefers-color-scheme as fallback.
  • Transition: add transition: background-color 0.3s ease, color 0.3s ease, border-color 0.3s ease to body and card elements for a smooth, non-jarring theme swap.
  • Position desktop: right side of nav, between nav links and right edge. No "Download CV" button in nav — it has been removed.
  • Position mobile: inside hamburger overlay, at the top — a clearly labelled row "Dark Mode / Light Mode" with the toggle.

OatLabs: The Boring Product Campaign

Route: /projects/oatlabs-boring-product-campaign · Stage 2 of HNG Marketing Fellowship

OATLABS CASE STUDY — FULL CONTENT

/projects/oatlabs-boring-product-campaign

01 · THE BRIEF (Business Challenge)

  • Stage 2 of the HNG Marketing Fellowship: select a low-interest, everyday product and build a complete strategy to grow it from $0 to $10K revenue. The task tested the ability to apply core marketing principles to drive growth from scratch — using creativity, structured thinking, and practical execution.
  • I chose oats — not despite the fact that they're boring, but because of it.

02 · MY ROLE & RESPONSIBILITIES

  • Title: Brand Strategist & Campaign Designer
  • Sole creator — all strategy, copy, and creative direction developed independently
  • Responsibilities: Brand naming and concept (OatLabs — The Morning Formula™) · Customer persona development (3 personas) · Full-funnel strategy (AIDA) · Ad copywriting (4 variations) · Email sequence (welcome → nurture → conversion) · Growth hack strategy (3 systems) · Landing page prototyping (2 live versions on Netlify) · Revenue roadmap ($0→$10K in 90 days) · Visual ad creative direction

03 · STRATEGY & APPROACH

  • Core insight: Oats have a retention problem. Consumers buy once, eat them plain, get bored, and never come back. The category is large ($9.5B globally) but repeat purchase rate collapses because nobody teaches people how to make them interesting. The "boring" label became the brand's superpower — the most powerful brand position is one competitors are too proud to claim.
  • Repositioning: Oats are a base, not a meal. OatLabs = Base (premium rolled oats) + Lab (mix-in system: spices, fruits, coffee, dates) + Ritual (repeatable morning). Tagline: "Your daily formula. Your flavour rules."
  • Three customer personas: Temi, 28, The Rushed Professional (Lagos, ₦150k+/mo, Instagram) · Kola, 21, The Campus Optimizer (university, ₦30k budget, TikTok) · Chidi, 33, The Fitness Experimenter (gym 5×/week, tracks macros)
  • Full AIDA funnel: Awareness (TikTok 'Boring Morning' series, paid social) → Interest (recipe carousels, UGC, email newsletter 'The Weekly Formula') → Decision (starter kit landing page, 7-Day Formula Challenge, retargeting) → Action (welcome email, referral programme 'Share a Formula', milestone rewards)

04 · EXECUTION & DELIVERABLES

  • 4 Ad Copies written: Ad 1 — oat drop-outs ("Oats didn't fail you. Nobody taught you how to use them.") · Ad 2 — fitness crowd ("Your protein shake has one flavour. Your mornings don't have to.") · Ad 3 — cold audiences ("They don't want you to know oats taste like this.") · Ad 4 — busy students/professionals ("4 minutes. 1 bowl. The most underrated breakfast upgrade.")
  • 3 Ad Creatives designed (Canva): "You don't hate oats. You hate boring." (split bowl before/after) · "Same oats. Different life." (Day 3 vs Day 30) · "You've been eating oats wrong." (editorial dark brown style)
  • 3-email sequence: Email 1 (Day 0, welcome) · Email 2 (Day 5, nurture — Coffee Lab Formula) · Email 3 (Day 8, conversion — 20% off Starter Kit code LABMEMBER20, 48hr urgency)
  • 3 Growth hacks: Formula Drop Model (limited 72-hour monthly drops with waitlist) · OatLabs Creator Kitchen (customer formula submissions, monthly winner featured) · Morning Routine Creator Partnerships (micro-influencers 5k–30k)
  • 2 live landing page prototypes (links in assets section below)
  • 10-slide pitch deck with revenue roadmap
  • 90-day revenue roadmap: Phase 1 (Days 1-30): $0→$1,500 (30 units) · Phase 2 (Days 31-60): $1,500→$5,000 (100 units, UGC + gym partnerships) · Phase 3 (Days 61-90): $5,000→$10,000 (200 units + 20 subscriptions)

05 · RESULTS & OUTCOMES (Projected)

  • $10,000 revenue target modelled across 90-day roadmap
  • 250 units sold + 20 active subscriptions by Day 90
  • 500+ email subscribers via 7-Day Formula Challenge
  • 200 UGC posts in Month 1 = projected 60,000 organic impressions at ₦0 spend
  • 5 gym partnerships → 1,000 warm leads at 15% conversion = ₦525,000 (~$350) from one partnership week
  • Note: This was a strategy project — outcomes are modelled projections from a ₦0 starting point, not live business results.

08 · CASE STUDY

MenuCard: Comprehensive Marketing Strategy

Route: /projects/menucard-comprehensive-strategy · Stage 3 of HNG Marketing Fellowship

MENUCARD COMPREHENSIVE — FULL CONTENT

/projects/menucard-comprehensive-strategy

01 · THE BRIEF (Business Challenge)

  • Stage 3 of the HNG Marketing Fellowship: build a full-scale, multi-channel marketing strategy grounded in real product understanding. Required direct engagement with a startup founder, keyword and market research, and an integrated strategy covering SEO, paid ads, social, content, and email — delivered as a professional presentation.
  • Product: MenuCard — a B2B SaaS product. QR-code-based digital menus with live inventory sync, real-time order management, sold-out auto-flagging, and analytics. Unlike generic QR menu tools, MenuCard is a control system for the full service shift — before, during, and after service.
  • The problem: Nigerian restaurants aren't losing money to bad menus — they're losing it to operational chaos. ~23% of potential revenue is lost during peak hours due to order errors, stock mismatches, and slow table turnover.

02 · MY ROLE & RESPONSIBILITIES

  • Title: Marketing Strategist
  • Responsibilities: Founder engagement and product deep-dive · Keyword research (Google Keyword Planner, Nigeria-specific) · Competitive landscape analysis · Multi-channel strategy (SEO, paid ads, social, content, email) · Audience segmentation (B2B and B2C) · Platform content strategy (Instagram, TikTok, LinkedIn) · Email funnel architecture (5 distinct audience segments) · Paid ads strategy (Google Search + Meta) · 90-day execution roadmap · 11-slide strategy presentation

03 · STRATEGY & APPROACH

  • Dual-audience insight: MenuCard is a B2B product (restaurant owners buy it) with a B2C surface (diners use it). The social strategy exploited this: content targeting restaurant owners builds the B2B pipeline; content targeting diners builds cultural pressure on restaurants to adopt.
  • SEO insight: Keyword Planner showed low Nigeria-specific search volumes — the category is still forming. 14 · MOTION SPEC

Animations & Interactions

Every animation should feel intentional, not decorative. Use Framer Motion throughout. Respect prefers-reduced-motion — wrap ALL animations and disable/reduce if true.

PAGE LOAD / HERO REVEAL

Staggered entry: eyebrow (0.2s delay) → h1 line 1 (0.4s) → h1 line 2 (0.6s) → sub-line (0.8s) → CTAs (1.0s). Each: y:20→0, opacity:0→1. Easing: easeOut. Duration per item: 0.5s. Disable slide if prefers-reduced-motion (opacity only).

SCROLL REVEAL

Every section's content animates in when entering the viewport. Framer Motion whileInView: opacity:0→1, y:20→0, duration 0.5s, once:true. Stagger children 0.08s. Disable if prefers-reduced-motion.

CARD HOVER

Project cards: whileHover: {y:-4, boxShadow:"0 16px 40px rgba(212,136,74,0.15)"}. Border transitions to rgba(212,136,74,0.5). Duration 0.2s. Disable transform if prefers-reduced-motion.

NAV SCROLL BEHAVIOUR

On scroll >60px: nav background animates to rgba(9,9,14,0.92) with blur. Transition 0.3s ease. Use scroll event listener + CSS transition or Framer Motion layout animation.

MOBILE MENU

Hamburger → X rotation: 0.3s. Full-screen overlay slides or fades in 0.25s. Nav links stagger in 0.05s delay per item. Close on link click or tap outside with reverse animation.

PAGE TRANSITIONS

Between routes: outgoing fades to opacity 0 over 0.2s, incoming fades in from opacity 0 with y:16→0 over 0.3s. Framer Motion AnimatePresence with mode="wait". Disable if prefers-reduced-motion.

CURSOR (DESKTOP ONLY)

Custom cursor: a small 8px circle in --accent that follows the mouse with a ~60ms lag (spring physics). On hovering links and buttons, the cursor scales up to 28px and transitions to a ring (hollow circle). Hide the default CSS cursor site-wide: cursor: none. Re-enable on mobile/touch. Implement with a global cursor component using useState for position + CSS transform. Disable entirely if prefers-reduced-motion.
